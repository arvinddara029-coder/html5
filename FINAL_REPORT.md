# SKYWARD — Single-Player Conversion: Final Report

The online multiplayer CrazyGames build has been converted into a polished,
stable, progression-driven **single-player adventure game**. Every online
system, dead menu and third-party dependency was removed; the world was
re-themed to a natural green wildscape; real pooling was added to the hot
combat paths; and the CrazyGames SDK now does **one job: ads**.

---

## REMOVED

- **Online play**: matchmaking UI, room codes, invites, PvP mode, remote-peer rendering, proxy entities, online leaderboard sync, `submitLeaderboard`, `recordOnline`, `onlineBest`.
- **Modules deleted**: `js/social.js`, `js/cloudsave.js`, `js/save-transfer.js`, `js/wave-resume.js` (+ tests updated).
- **Menus removed**: Credits, Assets archive, Resume Wave settings row, "Take Your Progress With You" export/import.
- **Dependency removed**: `assets/vendor/peerjs` (PeerJS no longer needed).
- **343 orphan asset files** (sound-effect packs, texture variants, previews never referenced by code, manifest or coverage) — see FILE CLEANUP.
- Every removed UI element was reference-searched repo-wide first; zero dangling handlers remain (verified by test + grep).

## OPTIMIZED

- **Object pooling (new)**: enemy bolts, player kunai, boss shockwaves and **all particles** now recycle through free-lists. Constructors transparently return pooled objects, so no call-site changed. Removal loops are O(1) swap-pop (no `splice`), and run/wave resets release objects back to the pools instead of dropping them to GC.
- **World rendering**: hills/forest/grass/bushes/rock art is generated **once** into cached offscreen canvases and blitted with parallax — zero per-frame allocation; decoration positions are deterministic hashes (no per-frame RNG).
- **Boot**: parallel staged loading (faster than sequential), real progress reporting, one-retry validation, lazy background streaming.
- **Hero art**: unchanged cache-invalidation fix retained (composite once, not per decoded asset).
- Spawn caps: enemy stage pools (max 40 on screen), particle cap 1000, projectile free-list caps (160/96/48).

## PROGRESSION

- World 1 unlocked at start; worlds 2–6 locked behind clearing the previous world (`profile.unlocked`, persisted).
- Per-world hero levels (`E.levels[chapter]`) advance on chapter clear; shown on world cards (`LV n`), the journey panel and the victory screen (`NEXT LEVEL · WORLD n · LV x`).
- Heroes gate progressively; locked heroes show unlock requirements in hero select; local save v2 with NaN/missing-field guards + `pvp→climb` migration keeps old saves valid.
- Coins/XP/gems loop intact: kills → coins/XP, bosses/chapters → gems, shop/fortune draw spend them.
- **Fortune Draw**: 250 coins per draw, odds displayed in-shop (300/600/1500/5000 coins, gems, XP, mystery gear), busy-guard prevents double-grant, free draw only via completed rewarded ad.

## ADS

- CrazyGames SDK is used **only** for ads + lifecycle events.
- **Interstitials** at safe breaks only: run end / game over, chapter victory, wave-climb floor checkpoints — gated by `canMidgame()` (180 s spacing + availability), never mid-combat.
- **Rewarded** (fortune-draw free spin): reward granted **only** in the ad-finished callback; error/unfilled → "no reward" notice.
- SDK failure or offline play never blocks the game (8 s init timeout, all calls null-guarded, env falls back to `disabled`).

## FILE CLEANUP

- Repo reduced **3164 → 2843 tracked files** (−321 after restoring false positives).
- Deletion method: repo-wide string scan of all JS/HTML/JSON + cross-check against `super-manifest.js` (2061 content files, test-enforced) and `super-content.js` coverage map; CSS `url()` references verified; dynamically composed names (`bg_<biome>.jpg`, `operators/<id>.svg`, `assets/super/` audio prefix) handled explicitly.
- 22 files initially flagged (fonts, kenney atlas XML, operator SVGs, coverage JSON) were **restored** after being caught by the CSS/atlas cross-check — no referenced asset was lost.
- Remaining ~2765 asset files are the game's content library (character layers, world packs, super content inventory) — deleting them would break content identity, which the brief forbids.

## TESTED

- `npm test`: **100 / 100 passing** (boot harness boots the real game in a stub DOM and drives frames; game/skyward/lobby suites cover combat, waves, bosses, saves, lobby).
- New tests: offline net-stub isolation, Fortune Draw economy (cost deduction, busy guard, free-draw no-charge, odds display), plus existing frame-budget (600 frames < 60 ms avg), hero-composite-once, and UI-walk tests re-verified after every change.
- `node --check` clean on all 54 JS modules; live HTTP smoke test (index, world.js, new SVGs, forest textures) all `200`.
- Playwright E2E suites updated (credits/save-transfer/resume-wave flows deleted); they need a browser and are not part of `npm test`.

## REMAINING LIMITATIONS

- **FBX/model pipeline**: three.js/playwright render tooling cannot run in this environment; guardian art is produced by the documented deterministic generator (`scripts/gen-guardians.cjs`) instead of 3D renders.
- **File-count target (<1400)**: the content library + test-enforced super-manifest (2061 files) keep the repo at 2843 files; reaching 1400 would require deleting in-use content, which the brief explicitly forbids.
- Playwright E2E suites require a real browser (not available here); coverage is via the stub-DOM harness instead.
- Audio decoding still requires a first user gesture (browser autoplay policy) — boot treats the audio stage as non-blocking by design.
